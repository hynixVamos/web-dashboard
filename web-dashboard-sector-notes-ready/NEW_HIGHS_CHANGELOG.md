# 신고가 리포트 — 실제 데이터 자동 갱신

## 완료된 동작

기존 Render용 Flask 앱에 `/new-highs`와 `/api/new-highs`를 추가했습니다. 새 프레임워크/패키지는 없습니다. 샘플 공급자는 제거했으며, 실제 수집 전에는 수집 대기 상태를 표시합니다.

수집 경로는 **NAVER/KRX KIND → new_highs_tracker → 백그라운드 실행 → 날짜별 JSON 캐시 → Flask → Jinja/vanilla JS**입니다. Flask 라우트는 외부 API를 호출하지 않습니다.

### 계산 정의

- 대상: KRX KIND의 코스피·코스닥 상장법인 대표 종목 코드. ETF/ETN, 코넥스, 별도 우선주 종목은 대상이 아닙니다. 거래정지/거래량 0은 제외 수에 표시됩니다.
- 20일/60일: 오늘의 수정 일봉 고가가 **오늘을 제외한 직전 20/60 거래일 고가의 최댓값을 초과**할 때. 동일 고가 재도달은 신고가로 세지 않습니다. 해당 길이의 이력이 없는 신규 상장 종목은 그 기간 판정에서 제외합니다.
- 52주: 오늘의 수정 일봉 고가가 **이전 364일(달력일) 내 고가**를 초과할 때. 52주 이력 확보가 필요합니다.
- 역사적: 상장일부터 일봉 이력이 확보된 경우만 이전 전체 고가와 비교합니다. 제공처 일봉 범위가 제한되어 **모든 종목의 역사적 신고가를 완전히 판정하는 것은 아닙니다**. 전체 이력 미확보 종목은 false와 all_time_verified=false를 함께 반환하고 화면에 검증 범위를 표시합니다.
- 각 기간을 독립 Boolean으로 저장합니다. 새 상장 종목은 역사적이지만 20일 이력이 아직 없을 수도 있습니다.
- 신규: 오늘 해당 기간의 신고가이며 직전 일봉 거래일에는 해당 기간의 신고가가 아닐 때.
- 연속: 기간별 연속 신고가 발생 거래일 수. 단순히 이전에 저장된 리포트의 존재 여부로 계산하지 않고 과거 일봉에서 계산합니다.
- 시가총액·거래대금: NAVER의 원 단위 Raw 필드를 각각 1억으로 나눕니다. 거래대금을 종가×거래량으로 추정하지 않습니다.
- turnover: 거래대금/시가총액 비율. 화면에서는 100을 곱해 %로 표시합니다.
- 등락률: NAVER 정규장 시세의 당일 등락률. NXT/시간외 값을 혼합하지 않습니다.
- 업종: KRX KIND 업종 분류이며 스크린샷의 분류명과 다를 수 있습니다.
- 동일 종목의 이름은 config.STOCK_UNIVERSE를 우선 재사용합니다.
- reason/memo는 실제 사람이 작성한 정보 연결을 위해 빈 문자열로 유지합니다. 임의의 상승 이유를 생성하지 않습니다.

### 자동 실행/장애 처리

- 기존 gunicorn.conf.py의 `post_fork → cache_refresh.start_background_refresh()` 호출을 유지합니다.
- 그 초기화 함수 안에서 신고가용 백그라운드 스레드를 한 번 시작합니다. 긴 전 종목 수집이 기존 GPU/Stocks/Hyperscaler/ADR의 30분 갱신을 막지 않도록 별도 스레드로 실행합니다.
- 평일 한국시간 15:30 이후 5분 간격으로 시세 제공 상태를 확인합니다. 하루 완료된 리포트가 있으면 같은 날짜를 재수집하지 않습니다. 휴일/주말에는 제공처 날짜를 기준으로 최신 완료일을 유지합니다.
- 따라서 결과 제공 시점은 15:30 정각이 아니라 다음 실행 시점 + 전 종목 수집 시간입니다. 서버가 계속 실행 중이어야 합니다.
- 요청 타임아웃, 최대 3회 재시도, 요청 간 간격, 날짜/종가 일치 검증을 적용합니다.
- OS 파일 잠금으로 같은 저장 경로를 사용하는 수집 프로세스 중복을 막습니다. 프로세스 종료 시 잠금이 해제됩니다.
- 25종목마다 진행 상태와 체크포인트를 저장해 중단 후 같은 날짜의 성공분을 재사용합니다.
- 부분 실패는 partial 상태와 실패 개수/코드를 표시하고 다음 주기에 재시도합니다. 정상 완료된 리포트를 부분 실패 결과로 덮어쓰지 않습니다.
- JSON은 임시 파일 작성 후 원자적으로 교체합니다. 기존 캐시 파일의 키/포맷/갱신 주기는 바꾸지 않았습니다.
- 화면은 60초마다 **내부 캐시 API만** 확인합니다. 과거 날짜 조회 중에는 날짜를 유지하고, 최신 버튼을 누르면 최신 결과를 따라갑니다.
- 날짜별 리포트는 운영 시작 후 축적됩니다. 과거 날짜의 시총/거래대금을 현재 값으로 만들어 채우지 않습니다. 수집 전에 지난 거래일의 리포트가 없으면 빈 상태를 표시합니다.

## Render 적용

1. ZIP의 프로젝트 소스를 기존 저장소에 반영합니다. 기존 API 키/환경변수와 시작 명령을 그대로 유지합니다.
2. 기존 Start Command: `gunicorn -c gunicorn.conf.py app:app`.
3. 실제 시세 수집에 **신규 API 키는 필요하지 않습니다**.
4. 날짜별 기록을 재배포/재시작 후에도 보존하려면 기존 Render 서비스에 Persistent Disk를 연결하고, 예를 들어 `/var/data`에 마운트합니다. 다음 환경변수를 추가합니다.

   `NEW_HIGHS_DATA_DIR=/var/data/new_highs`

   이 값은 실제 디스크 마운트 아래를 가리켜야 합니다. 환경변수만 설정해도 디스크가 생성되는 것은 아닙니다. 디스크 추가/요금 변경이나 운영 서비스 배포는 이번 작업에서 실행하지 않았습니다.
5. 미설정 시 `<프로젝트>/data/new_highs`에 저장됩니다. Render 기본 파일시스템에서는 재시작/재배포 시 그 파일들이 사라질 수 있습니다.
6. 첫 장 마감 수집 후 신고가 탭에서 날짜, 수집 상태, 분석/실패 수를 확인합니다. Render 서버에서도 NAVER/KRX KIND 외부 접근이 가능해야 합니다. 제공처 차단/형식 변경 시 오류가 표시되고 직전 결과가 유지됩니다.
7. 필요 시 서버 Shell에서 `python new_highs_tracker.py`로 수집을 실행할 수 있습니다. `--force`는 당일 완료분도 재수집합니다. 장중에는 두 방식 모두 수집하지 않습니다.

Render 디스크 설명: https://render.com/docs/disks
KRX KIND 상장법인 목록: https://kind.krx.co.kr/corpgeneral/corpList.do?method=loadInitPage
NAVER 수정 일봉을 사용하는 FinanceDataReader 구현 참고: https://github.com/FinanceData/FinanceDataReader/blob/master/src/FinanceDataReader/naver/data.py

## 남아 있는 데이터 범위

20일/60일/52주와 이력 확보 종목의 역사적 신고가는 실제 데이터로 자동 계산됩니다. 전체 종목에 대한 완전한 역사적 신고가를 요구하면 상장일부터의 수정 가격을 보장하는 데이터 공급자를 추가해야 합니다. 메모/이유의 저장·편집 및 자동 생성은 연결하지 않았습니다.

현재 단계의 운영 배포는 사용자의 기존 저장소/Render에 소스를 반영해야 완료됩니다. 이 ZIP을 생성하는 것만으로 이미 운영 중인 서비스가 변경되지는 않습니다.
