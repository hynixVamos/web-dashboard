# 신고가 수동 기록

- 종목을 클릭하면 섹터와 신고가 이유를 입력할 수 있습니다.
- 매번 저장한 입력은 수정·덮어쓰기 없이 별도 기록으로 누적됩니다.
- 최신 수동 섹터는 같은 종목의 모든 조회 날짜에 적용됩니다.
- 이유는 입력 시 선택한 리포트 날짜의 표·메모 추출에 반영됩니다.
- 상세창의 누적 입력 기록에서 다른 날짜의 기록도 확인할 수 있습니다.
- 빈 섹터는 기존 분류를 유지합니다. 섹터만 또는 이유만 저장할 수 있습니다.
- 공개 페이지의 기록은 방문자가 함께 조회·입력하는 공용 기록입니다. 개인별 저장소나 작성자 인증은 포함하지 않습니다.

## 저장소

SQLite `high_notes` 테이블에 저장합니다. 수집기가 덮어쓰는 JSON 보고서와 분리되어 있습니다.
로컬 기본 경로는 `data/manual_notes.sqlite3`이며 `NEW_HIGHS_NOTES_DB` 환경변수로 변경할 수 있습니다.

현재 서비스의 영구 디스크가 `/var/data`에 연결되어 있음을 확인했습니다.
Render에서는 이 마운트를 확인하고 `/var/data/manual_notes.sqlite3`를 자동으로 사용합니다.
현재 서비스에는 별도 환경변수 설정이 필요하지 않습니다.
다른 마운트 경로를 사용하는 서비스에서는 실제 영구 디스크 하위 경로를 명시할 수 있습니다.

```
NEW_HIGHS_NOTES_DB=/var/data/manual_notes.sqlite3
```

위 예시는 디스크가 `/var/data`에 마운트된 경우입니다. 실제 마운트 경로가 다르면 그 하위 경로를 사용하세요.
단순히 환경변수만 추가하면 영구 저장이 보장되지 않습니다. 영구 디스크가 없는 경우 먼저 저장소를 준비해야 합니다.
Render 환경에서 이 변수도 없고 `/var/data` 마운트도 없으면 기존 리포트 조회는 유지하지만 기록 API는 503을 반환합니다.
임시 디스크에 저장하고 성공으로 표시하는 것을 방지하기 위한 설정입니다.
기존 디스크를 다른 경로로 재마운트하거나 기존 리포트 데이터를 이동할 필요는 없습니다.

공식 문서: https://render.com/docs/disks

배포 후 기록 보존 검증은 별도의 테스트 환경에서 저장 → 앱 재시작 → 조회 → 재배포 → 조회 순으로 진행하세요.
백업은 SQLite backup API를 사용하고, 운영 중인 DB 파일을 임의 복사해 백업하지 마세요.
